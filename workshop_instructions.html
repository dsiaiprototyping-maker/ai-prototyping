What you're building

Each team builds a blog post about the DSI AwayDay — the event you're attending right now. Your team's blog post lives in DSI-Awayday-blog.html on a branch your cloud session creates. Capture what happened, what you learned, and what mattered. Make it look good.

The page you're reading is the workshop brief. It does not change. Everyone in the room is working from this same set of instructions — your branch contains your blog, not a copy of these instructions.

How to log in

  1. Install the Claude Code app.
  2. Sign in with email: dsi.ai.prototyping@gmail.com.
  3. Enter the login code (the organizers will read it out).
  4. In the app, go to Code → New Session and send your first message to start the session.
  5. Select the Haiku model.
  6. Rename the session to something like your team name (top of the session panel).
  7. Ask the agent to rename the branch to team-<your-name> so the preview URL you share is readable.
The agent will remind you. Your first message in a fresh session triggers a short setup checklist before any feature work starts: confirm the renames, and tell the agent who your authors are.

Suggested blog structure

These are the components of a good blog post. Use them as a guide — only authors are strictly required.

  • Authors MUST — your team members' names as the byline. The agent will ask if missing at commit time.
  • Date AUTO — the agent sets this at commit time.
  • Away Day Agenda SHOULD — the schedule of the day, what happened and when.
  • What We Worked On SHOULD — a narrative section describing the problem your team explored, your approach, and what you discovered.
  • Key Takeaways SHOULD — a short bullet list of the most important things your team learned.
  • Comments widget at the end SHOULD — a name + comment form you build yourself, persisted via localStorage, rendering submitted comments below. The starter template has a placeholder — the JS is yours to write.
Comments widget hint. Persist to a key like awayday_blog_comments. On load, parse and re-render. Each record has a name, comment text, and a timestamp. Newest first.

How to preview

When you want to see your work, ask the agent to preview DSI-Awayday-blog.html.

The agent will commit the latest changes, generate the correct preview URL for your team's branch, and give you the link to share when it's time to show your work.

How your work will be evaluated

  • Completion of features — how much of the suggested blog structure you got working end-to-end.
  • General UI aesthetics — does the page look like a real blog post? Typography, spacing, colour, layout.
  • Use of skills & best practices — the quality of your prompting, sensible commits, clean structure, and using the tools the right way.

Extra features to explore

Once the core sections are done, try building one of these. Each is a self-contained JS or CSS challenge.

  • Dark mode toggle — a button in the header that switches the page between light and dark themes. Swap a data-theme attribute on <body> and use CSS variables to restyle. Persist the preference in localStorage so it survives a reload.
  • Reading progress bar — a thin accent-coloured bar fixed to the top of the viewport that fills from left to right as the user scrolls down the page. One scroll event listener and a CSS width calculation.
  • Back to top button — a button that appears once the user scrolls past the hero, and smooth-scrolls back to the top when clicked. Show/hide it by toggling a class on a scroll event.
  • Table of contents — automatically generated from the <h2> headings on the page. Render it as a sticky panel on the left at wide viewports (collapsed on mobile). Clicking an entry smooth-scrolls to that section.

Tips for shipping features

  • Be specific. "Make a hero with a centred title, a subtitle in muted grey, and a full-width cover image" beats "make a nice header".
  • Include planning and interview phases. Ask the agent to plan first, then interview you for missing details before it writes code.
  • Iterate. Ship a rough version, then improve it one piece at a time. Don't try to one-shot the whole page.
  • Give feedback. Tell the agent what works, what feels wrong, and what to change next.
