What you're building

Each team builds a blog post about the DSI AwayDay — the event you're attending right now. Your team's blog post lives in DSI-Awayday-blog.html on a branch your cloud session creates. Capture what happened, what you learned, and what mattered. Make it look good.

The page you're reading is the workshop brief. It does not change. Everyone in the room is working from this same set of instructions — your branch contains your blog, not a copy of these rules.

How to log in

  1. Install the Claude Code app.
  2. Sign in with dsi.ai.prototyping@gmail.com.
  3. Enter the login code (the organizers will read it out).
  4. In the app, go to Code → New Session and send your first message to start the session.
  5. Rename the session to something like your team name (top of the session panel).
  6. Rename the branch to team-<your-name> so the preview URL you share is readable.
The agent will remind you. Your first message in a fresh session triggers a short setup checklist before any feature work starts: confirm the renames, and tell the agent who your authors are.

Suggested blog structure

These are the components of a good blog post. Use them as a guide — only authors are strictly required.

  • Hero / title image SHOULD — a header with the post title and a cover image.
  • Authors MUST — your team members' names as the byline. The agent will ask if missing at commit time.
  • Date AUTO — the agent sets this at commit time.
  • Body — at least 3 sections SHOULD — suggested: Agenda / Purpose, UI overhaul, Image gallery or visual elements.
  • Comments widget at the end SHOULD — a name + comment form, persisted via localStorage, rendering submitted comments below.
Comments widget hint. Persist to a key like awayday_blog_comments. On load, parse and re-render. Each record has a name, comment text, and a timestamp. Newest first.

Rules

  • Pure HTML, CSS, and vanilla JavaScript only. No npm packages, no frameworks, no build tools.
  • One <style> block in <head>. One <script> block at the end of <body>.
  • No inline styles. No external .css or .js files.
  • CDN allowed for Google Fonts and Lucide icons only.
  • Prefer the :root CSS variables for any brand or repeated colour. Add new variables if you need them; don't rename or remove the existing six.
  • Mobile-responsive — use relative units, sanity-check at 375px.
  • Semantic HTML — proper elements, not div soup.
  • Photos must be committed to assets/awayday/<descriptive-name>.<ext> and referenced via the raw-GitHub URL for your current branch. Relative paths break in htmlpreview.

How to preview

Previews go through htmlpreview.github.io. The URL has the shape: 

https://htmlpreview.github.io/?https://raw.githubusercontent.com/<owner>/<repo>/<branch>/<file>

There is one rule about which <branch> goes in:

  • These instructions always preview off main — they don't change.
  • Your blog always previews off your team's current branch — that's where the edits live.
Your agent will print the right URL for you after every change to DSI-Awayday-blog.html. Share that URL when it's time to show your work.

How you'll be reviewed

  • Completion of features — how much of the suggested blog structure you got working end-to-end.
  • General UI aesthetics — does the page look like a real blog post? Typography, spacing, colour, layout.
  • Use of skills & best practices — the quality of your prompting, sensible commits, clean structure, and using the tools the right way.

Tips for prompting

  • Be specific. "Make a hero with a centred title, a subtitle in muted grey, and a full-width cover image" beats "make a nice header".
  • Iterate. Ship a rough version, then improve it one piece at a time. Don't try to one-shot the whole page.
  • Show examples. Paste a snippet you like, name the blog post you want it to feel like, or describe the vibe in plain language.
  • Ask the agent to plan first. "Before writing code, tell me what you'll change and where" surfaces misunderstandings cheaply.
