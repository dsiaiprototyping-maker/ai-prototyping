DSI · AWAY DAY SLIDE 02 · LLM CHAT VS AI AGENT HARNESS MAY 2026
Foundations

LLM Chat vs AI Agent Harness

LLM / Chat Interface
You ask a question, it gives an answer
Mostly conversation
Best for brainstorming, writing, summarising
Human does most of the execution
Output is usually text
Claude / Chat UI — strong for thinking, explaining, drafting, refining
AI Agent Harness
You give a goal, it can take actions to achieve it
Conversation plus tools, memory, permissions, and workflows
Best for building, checking, testing, fixing, and iterating
Agent can do parts of the execution under supervision
Output can be code, edits, screenshots, test results, PRs, browser actions
Claude Code — strong for acting inside a working environment with files, tools, terminal, browser, and review loops

A chat interface gives you answers. An agent harness helps turn answers into completed work.

DSI · AWAY DAY SLIDE 04 · SETTING CLAUDE UP FOR SUCCESS MAY 2026
Configuration

Setting Claude Up for Success

01 · Git
Version Control

Gives Claude a safety net — it can diff, revert, and branch. Commit history is context Claude can read and reason about. Branches let Claude work in isolation before you review.

02 · Memory
Persistent Facts

Persistent facts across sessions. Stored as markdown files Claude reads at start of conversation. Types: user profile, project state, feedback corrections, external references.

03 · CLAUDE.md
Rules File

Project-level instructions checked into the repo. Define stack constraints, naming conventions, scope limits. Claude treats this as the source of truth for how to work in the project.

04 · Skills
Slash Commands

Reusable capabilities invoked with a slash command. Examples: /review, /plan, /security-review, /init, /graphify. Custom skills can encode team-specific workflows.

05 · Permissions
Allowlist

Explicit allowlist of what Claude can run automatically. Reduces friction for low-risk commands (read, test, lint). High-risk actions (push, deploy, delete) still prompt for approval.

The more context and guardrails you give Claude upfront, the less supervision it needs mid-task.

DSI · AWAY DAY SLIDE 05 · BUILDING WITH CLAUDE — FROM PROMPT TO SHIPPED MAY 2026
Process

Building with Claude — From Prompt to Shipped

01
Good Prompting
Point at what you see: "the hero section looks cramped on mobile"
Name the constraint: "only change the CSS, don't touch the HTML"
One visible goal per prompt — if you can screenshot it, it's scoped right
02
Plan Phase
Ask Claude to plan before it codes: "what would you change and why?"
Read the plan — reject wrong assumptions before a single line is written
Opus for tricky decisions, Sonnet for most feature work
03
Interview Phase
Claude asks questions before acting — answer them, don't skip
Hidden conflicts surface here: "that id is used by another team's section"
Shared understanding reached here saves rework later
04
Screenshot Feedback
Take a screenshot of your browser at any point
Paste or attach it: "this is what I see — fix the spacing"
Claude reads the visual and corrects accordingly
05
Iteration Loop
prompt → Claude edits → you refresh → screenshot if something looks off
Small focused prompts give you a short, reviewable diff each time
Commit after each working step — safety net if the next prompt goes wrong
↺ loop · iterate · ship

Build in short loops: prompt, look, screenshot, correct — the browser is your shared source of truth.
